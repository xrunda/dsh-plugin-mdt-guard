# M1 Server Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dependency-free server config loader and validator for the MDT guard bundle, with PRD defaults, explicit validation errors, and no secret leakage.

**Architecture:** Keep `validateConfig(input)` pure and separate from `loadConfig({ filePath? })`, which reads `~/.dsh/mdt/guard.json` by default and allows test-only path injection. Normalize nested defaults, replace arrays as a whole, reject unknown keys, and surface sanitized `ConfigError`s; do not wire the module into `index.js` in this issue.

**Tech Stack:** Native Node.js ESM, built-in `node:test`, `node:fs/promises`, and `node:os`; no runtime dependencies.

---

## File Map

- Create `config.js`: defaults, `ConfigError`, pure normalization/validation, default path resolution, and async JSON loading.
- Create `tests/config.test.mjs`: tests for normalized defaults, schema validation, file reads, and secret-safe errors using temporary directories.
- Modify `package.json`: export `./config` and add `config.js` to the shipped file allowlist.
- Modify `tests/plugin-skeleton.test.mjs`: assert that the config entry is exported and included in the bundle.
- Create `Docs/guard.example.json`: credential-free example with an `.invalid` endpoint and the documented config shape.

## Task 2: Implement pure defaults and validation

**Files:**
- Create: `config.js`
- Test: `tests/config.test.mjs`

- [ ] **Step 1: Add frozen, explicit PRD default values**

  Define defaults for `enabled`, classifier timeout/token limit, context turns, `failOpen`, placeholder rule arrays, the exact PRD refusal string, audit settings, and placeholder tool arrays. Keep `baseUrl`, `model`, `apiKey`, and `caCertFile` absent unless supplied. Avoid exporting mutable nested defaults directly; return fresh normalized objects.

- [ ] **Step 2: Add a sanitized `ConfigError` type**

  Extend `Error` with a stable `code` and optional field/path metadata. Construct messages from fixed templates plus field names only. Do not attach parser, filesystem, or input-value details as `cause`.

- [ ] **Step 3: Implement pure merge and validation**

  Implement `validateConfig(input)` to require a plain object, reject unknown keys recursively, deep-merge nested objects, and replace arrays wholesale. Validate field types, non-empty strings, absolute HTTP(S) `classifier.baseUrl`, and the approved numeric ranges. Require `classifier.baseUrl` and `classifier.model` only when normalized `enabled` is `true`; continue validating any optional fields supplied while disabled. Validate rule/tool arrays as string arrays without compiling regexes or assigning policy semantics.

- [ ] **Step 4: Run the pure validator tests**

  Run: `node --test tests/config.test.mjs`

  Expected: all pure validation tests pass; loader tests are added in Task 3.
