# M1 Built-in Rules Implementation Plan

> **For agentic workers:** Follow the tasks in order. Do not skip steps.

**Goal:** Add built-in G/H hard-deny and C/D fast-allow rules, configurable
through the existing server config, with stable rule identities for audit and
explicit invalid-regex errors.

**Architecture:** A dependency-free `rule-defaults.js` holds the rule catalog
and metadata. `config.js` uses the default sources and validates rule regex
syntax. `rules.js` compiles the effective sources once and evaluates messages
synchronously: hard deny first, then fast allow, otherwise `unknown` for the
classifier. `index.js` is not wired.

**Tech Stack:** Native Node.js ESM, built-in `node:test`, no runtime
dependencies.

---

## File Map

- Create `rule-defaults.js`: frozen built-in rule catalog, default source
  arrays and the shared regex flags.
- Modify `config.js`: default to built-in rule sources, treat an empty array
  as "use defaults", reject invalid regex with `CONFIG_RULE_INVALID`.
- Create `rules.js`: `compileRules(config)` and `evaluateRules(ruleSet, text)`.
- Create `tests/rules.test.mjs`: table-driven rule, priority, override,
  normalization and sanitized-error tests.
- Modify `tests/config.test.mjs`: built-in defaults, empty-array override,
  custom override and invalid-regex contract.
- Modify `package.json`: export `./rules`, ship `rules.js` and
  `rule-defaults.js`.
- Modify `tests/plugin-skeleton.test.mjs`: assert the new export and files.
