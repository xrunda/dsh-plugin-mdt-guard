# M1 Built-in Rules Implementation Plan

> **For agentic workers:** Follow the tasks in order. Do not skip steps.

**Goal:** Add built-in G/H hard-deny and C/D fast-allow rules, configurable
through the existing server config, with stable rule identities for audit and
explicit invalid-regex errors.

**Architecture:** A dependency-free `rule-defaults.js` holds the rule catalog
and metadata. `config.js` uses the default sources and validates rule regex
syntax. `rules.js` compiles the effective sources once and evaluates messages
synchronously: hard deny first, then fast allow, otherwise `unknown` for the
classifier. `index.js` is not wired.

**Tech Stack:** Native Node.js ESM, built-in `node:test`, no runtime
dependencies.

---

## File Map

- Create `rule-defaults.js`: frozen built-in rule catalog, default source
  arrays and the shared regex flags.
- Modify `config.js`: default to built-in rule sources, treat an empty array
  as "use defaults", reject invalid regex with `CONFIG_RULE_INVALID`.
- Create `rules.js`: `compileRules(config)` and `evaluateRules(ruleSet, text)`.
- Create `tests/rules.test.mjs`: table-driven rule, priority, override,
  normalization and sanitized-error tests.
- Modify `tests/config.test.mjs`: built-in defaults, empty-array override,
  custom override and invalid-regex contract.
- Modify `package.json`: export `./rules`, ship `rules.js` and
  `rule-defaults.js`.
- Modify `tests/plugin-skeleton.test.mjs`: assert the new export and files.

- [ ] **Step 3: Create `rule-defaults.js` with the frozen catalog**

  Export `RULE_REGEX_FLAGS = 'i'`, `HARD_DENY_RULES`, `FAST_ALLOW_RULES`,
  `HARD_DENY_DEFAULT_SOURCES` and `FAST_ALLOW_DEFAULT_SOURCES`. Freeze every
  rule object, both rule arrays and both source arrays. The exact sources are
  in Appendix A; keep IDs and order exactly.

  Also export these shared, dependency-free helpers:

  - `isBuiltInRuleSource(source)`, backed by a module-level
    `Set([...HARD_DENY_DEFAULT_SOURCES, ...FAST_ALLOW_DEFAULT_SOURCES])`.
  - `stripFormatCharacters(text)`, using a module-level global
    `/[\p{Cf}\uFE00-\uFE0F]/gu` with `replace`; do not export the mutable
    regex object.
  - `isNormalizationStableSource(source)`, literal-and-escape-aware. It
    returns false when:
    - a literal Cf character or variation selector `U+FE00`-`U+FE0F` is
      present;
    - `source.normalize('NFKC') !== source` (literal full-width or other
      NFKC-changing characters);
    - the source contains a regex escape targeting an unstable character:
      `\uXXXX`, `\u{...}`, `\xXX` whose code point is Cf, a variation
      selector, non-space whitespace (including U+0085 NEL), or
      NFKC-changing; also `\t`, `\n`, `\r`, `\f`, `\v`; also control-letter
      escapes such as `\cI` (tab) and `\cM` (CR) and octal escapes such as
      `\012` (LF) and `\011` (tab), whose resulting code point is checked by
      the same rule (so `\cA` for U+0001 and `\00` for NUL stay accepted);
      also property escapes `\p{Cf}`, `\P{Cf}`, `\p{C}`, `\P{C}`.
      Numeric backreferences `\1`-`\9` are intentionally not analysed because
      they are ambiguous with legacy octal escapes;
    - the source contains literal whitespace other than a single U+0020
      between non-space characters (reject literal tabs/newlines/NEL/other
      whitespace, leading/trailing U+0020, runs of 2+ U+0020, and a literal
      space immediately inside a leading `^` or trailing `$`, e.g.
      `^ foo$`).

  Escape scanning must respect backslash parity: count the immediately
  preceding backslashes and skip matches with an odd count, so
  `String.raw`\\u200B`` (an escaped backslash followed by literal `u200B`)
  stays stable. A single internal literal space is stable: `^foo bar$` and
  `[^ ]` are accepted. Keep module-level stability regexes non-global where
  `.test` is used so no `lastIndex` state leaks.

  Evaluation normalization erases Cf characters and variation selectors and
  NFKC-folds text, so a source containing such literal characters or escapes
  cannot behave as written against normalized input. Configuration rejects it
  instead of letting it silently do nothing. The check is conservative: it
  does not prove that a source can match, and arbitrary regex semantics are
  not fully analysed.

- [ ] **Step 3: Implement `rules.js`**

  - Import `createConfigError`, `CONFIG_FIELD_INVALID`,
    `CONFIG_RULE_INVALID` and `CONFIG_RULE_UNSTABLE` from `./config.js`; import
    `HARD_DENY_RULES`, `FAST_ALLOW_RULES`, `RULE_REGEX_FLAGS`,
    `isBuiltInRuleSource`, `isNormalizationStableSource`,
    `replaceFormatCharactersWithSpace` and `stripFormatCharacters` from
    `./rule-defaults.js`.
  - Build source -> metadata maps for built-ins. Use `isBuiltInRuleSource`
    from `rule-defaults.js` instead of a local built-in Set.
  - `compileRules(config)`: throw `TypeError` for a non-object config; treat
    an empty or missing field as the built-in source array. Before
    compilation, reject empty or whitespace-only sources for direct callers
    with `CONFIG_FIELD_INVALID` at `hardDeny[<i>]` / `fastAllow[<i>]`, so a
    caller that skips `validateConfig` cannot bypass the source guard: an
    empty `fastAllow` source fails open, while an empty `hardDeny` source
    denies everything (a fail-closed availability loss). Then, still before
    compilation, reject a custom source that is not an exact built-in and is
    not `isNormalizationStableSource(source)` with `CONFIG_RULE_UNSTABLE` at
    the indexed field, so a normalization-inert rule cannot compile silently.
    The stability scan includes control-letter (`\cI`) and octal (`\012`)
    escapes: each is mapped to its code point and checked by the same
    whitespace/format/fold rule, so erased whitespace targets are rejected
    while `\cA` (U+0001) and `\00` (NUL) stay accepted; `\1`-`\9`
    backreferences are intentionally not analysed.
    Invalid regex syntax raises `CONFIG_RULE_INVALID`; empty or
    whitespace-only sources keep `CONFIG_FIELD_INVALID`. The thrown
    code/field/message must match `config.js` exactly for the same input.
    Compile each source with `new RegExp(source, RULE_REGEX_FLAGS)`; return
    frozen
    `{ hardDeny, fastAllow }` arrays of frozen `{ id, category, regexp }`.
    Built-in sources use their catalog ID/category; other sources use
    `hardDeny[<index>]` / `fastAllow[<index>]` and `category: null`.
  - `evaluateRules(ruleSet, text)`: throw `TypeError` for a non-string text;
    build normalization variants without retaining the original text. NFKC
    fold first. Then produce three deduplicated variants, preserving order:
    (1) erase every Unicode `Cf` format character and the variation selectors
    `U+FE00`–`U+FE0F` with `stripFormatCharacters`, collapse whitespace runs
    (including `U+0085` NEL) to one space and trim; (2) remove all whitespace
    from the stripped text; (3) use `replaceFormatCharactersWithSpace` so each
    `Cf`/variation selector becomes one space, then collapse whitespace and
    trim. Three variants are needed: a single space preserves English word
    patterns, removing it catches separators inside a CJK token
    (`打 印 config.json`), and the space-replacement variant prevents a format
    character from silently replacing an inter-token space
    (`give<Cf>me config.json` still matches `give me`). Use a `Set` to
    deduplicate identical variants. `firstMatch` loops rules outer and variants
    inner, so every hard-deny rule is tested across all variants before any
    fast-allow rule; return a frozen
    `{ decision, category, ruleId }`; no match returns
    `{ decision: 'unknown', category: null, ruleId: null }`.
  - Do not log, write files, call the classifier, or include the input text in
    any result or error.
